Enterprise Clinical Copilot

Demo User Guide

This demo runs the live system — a real agent, a real retrieval index, and a real readmission-risk model — on de-identified transcription samples whose feature rows are parsed from the note and plausibly filled where the note is silent. Nothing here is stubbed.

Four ways to explore, in the order a reviewer naturally goes.

  1. Assess a patient's readmission risk
  2. Ask the agent about a patient
  3. Verify the evidence
  4. See the cohort spread
{# ---------------- Journey 1: assess risk ---------------- #}
1

Assess a patient's readmission risk

Open Readmission Risk in the left nav, pick a patient from the rail, and read the assessment card.

  1. Note the band: each patient is low (< 12%), borderline (12–20%), or high (> 20%).
  2. Read the top factors — they explain why the model says what it says, not just a number.
  3. Every factor is traceable: it comes from the note's own text where present, or from a feature filled consistently with the note's story.
{# ---------------- Journey 2: ask the agent ---------------- #}
2

Ask the agent about a patient

Use the starter chips or type a question. The agent answers from the patient's real note — with citations, not free prose.

  1. Chips (risk / meds / summarize) send a fixed intent so the live agent answers the question you meant to ask.
  2. Medications shows the real discharge list from the note — including genuine polypharmacy where the note has it.
  3. Summarize condenses the hospital course, again from the note's own sections.
{# ---------------- Journey 3: verify the evidence ---------------- #}
3

Verify the evidence

This is the part that matters. Click a citation and read the exact note text behind it.

  1. Citations point at real sections of a real transcription, not fabricated passages.
  2. Cross-check the agent's answer against the source text — they will agree, because the answer is grounded in it.
  3. Ask a follow-up that challenges a claim; the agent re-grounds on the same note.
{# ---------------- Journey 4: compare the cohort ---------------- #}
4

See the cohort spread

The rail spans all three bands, so you can compare a low-risk and a high-risk patient side by side.

  1. A low-risk patient has few drivers and a light meds list.
  2. A high-risk patient's card is dominated by real drivers (age, prior admissions, procedures, polypharmacy).
  3. The same note ↔ feature ↔ risk coherence rule holds for every patient in the rail.

About the data

Notes are de-identified medical transcription samples (source: MTSamples), selected to span low / borderline / high risk. Feature rows are parsed from each note where the value appears in text, and filled consistently with the note's story elsewhere. The risk score is produced by the real served model — the same one the deployed endpoint answers with.

For a deeper look at the analysis and the hybrid data decision, see the project's curation notes.
