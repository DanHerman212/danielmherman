The shell is a collapsible menu on the left and the conversation beside it. There is no patient rail. Patient selection lives in the ask bar as an `@` command, and the sidebar lists the threads those selections produced — one thread per patient, because a conversation is about exactly one patient. The menu carries three labels — New Conversation, Discover, Tools. Discover and Tools are placeholders, rendered `disabled` so that a control doing nothing cannot be mistaken for a feature that is broken. History is gone: there was a control that revealed the thread list, and a list a reader has to ask for is a list they have to know is there. Account actions are split. The user guide and the request count sit in the menu at the top right of the page — the same markup the front door uses, and the same script drives it, so the two menus cannot drift apart. Sign-out sits under the identity at the foot of the sidebar. The conversation is one continuous column. Turns are not cards and do not fold: each one is headed by the question that asked it, and the heading pins to the top of the scroll area while its own answer passes beneath it. {% endcomment %} {% block title %}Enterprise Clinical Copilot{% endblock %} {% block content %}

    {% comment %} The question and the run used to sit here, as one box and one status row for the page. They are now part of a turn: the question is that turn's header and the status row is its footer, so a conversation can show twenty of each without one turn's row standing in for another's. The client builds them (`createTurn`) for a live turn and for a turn restored from the store alike. {% endcomment %}
    {% comment %} The context bar: what the whole thread is about, and how long the store will keep it. The patient is a property of the conversation rather than of the turn being read, so it is stated once above the feed. Deliberately not here: the turn counter. "Turn 3 of 20" is the system's bookkeeping, not the clinician's, and a limit they can run into without having done anything wrong is not something to keep in front of them. {% endcomment %}
    {% comment %} The conversation: one continuous column of turns, oldest first. This is the only zone that scrolls, and the turns are constrained to a centred column so they do not run flush against the sidebar. There is no navigator above the composer and no card to fold away. Each turn's question heads it and sticks to the top of the scroll area while its own answer passes under it, so the reader always has the question that the text in front of them is answering — which is what the navigator was for, without a second control to keep in step with the first. The blocks are built by the client and nothing in them is addressed by a page-wide id, because a conversation holds several canvases, several citation triggers and several status rows at once. `data-renderer-url` names the A2UI bundle for the feed as a whole: it is fetched on demand, once, and mounted per turn — never at page load, because its module graph is large and nothing on first paint needs it. {% endcomment %}
